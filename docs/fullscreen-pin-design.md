# 全屏 Pin 设计草案

2026-10-06。用户选定「刘海贴边」后，0.43 源码已接入该形态及无刘海屏的小胶囊回退。下文保留完整设计方向；侧边挂签和按应用记住位置尚未实现。

## 当前问题

0.42 的 `DockPlacement.swift` 接收 `fullscreen`，却没有使用它，进入全屏仍沿用桌面布局。0.43 为全屏 Pin 增加独立展示状态，并让临时展开使用刘海下方布局。全屏检测改为检查目标屏幕的可见窗口，不再只检查全局前台应用；工作屏幕仍优先内置刘海屏，不随鼠标在多屏之间跳动。

此外，固定音乐胶囊仍可能保持较宽的歌曲/歌词布局；穿透能减少点击拦截，但不能减少视觉遮挡与动态内容对注意力的影响。

- [Droppy 文档](https://getdroppy.app/docs/notch)：按显示器选择 notch/island，提供全屏隐藏、仅隐藏媒体、Mission Control 隐藏、按组合键才显示。借鉴明确的显示策略及不同屏幕形态。
- [NotchNook](https://lo.cafe/notchnook)：widgets/live actions/files shelf 的工具中心，支持无刘海屏和多屏。完整功能层可参考，常驻全屏层不适合照搬。

以上依据官网、文档与公开源码；未安装这些应用，不代表已实测其全屏兼容性。只借鉴交互思路，不复制代码或美术资源。

## 建议形态

用户明确要求「常驻，不隐藏」。默认选择「刘海贴边」，无刘海屏使用「小胶囊」，也提供「侧边挂签」。全屏 Pin 始终有可见的状态与操作入口，进入全屏只缩小，不自动隐藏。

### 刘海贴边

适用于存在真实刘海安全带的显示器。左右两翼位于刘海高度内，中间硬件区域留空，不在刘海下方常驻额外内容。基于屏幕实际安全带与刘海边界计算尺寸，不写死相机宽度；两翼参考 30–40 pt 与 50–64 pt，实际高度不超过安全带。空间不足或应用内容延伸到安全带时回退小胶囊/侧边挂签，不能假设所有全屏应用都留下空白顶部。

形态为安静的深色底、小球模块色点、稳定的短数字/图标。不显示循环歌词、滚动歌名、频谱或持续扫光。彩色仅用于小球和一条细进度标记。由于深色底板固定，使用稳定浅色文字；不在这里重复采样背景而反复变色。

### 小胶囊

无刘海屏参考 120–156 × 26–28 pt，最多一行。保持现有圆角、模块色点和柔和玻璃语言，但底板有足够对比度，不以提高透明度替代减少占用。默认顶部居中，可手动选择顶部角落并按显示器保留；不存在对所有应用都安全的固定坐标，因此提供侧边位置及按应用记忆。

### 侧边挂签

顶部已被工具栏占满时，使用靠左/右边缘的小挂签，参考 64–88 × 28 pt，只显示模块色点与短状态。可沿边缘调整高度，按应用和显示器保留，避免每次进入全屏再拖动。点击向屏幕内部展开，不向屏幕外溢出。无持续波动或跑动效果，后台计时、播放和事件同步继续。

## 五个模块的常驻信息

| 模块 | 极简状态 | 点击后的内容 |
| --- | --- | --- |
| 音乐 | 封面/音乐小球 + 播放或暂停图标；可选细进度 | 固定歌名与歌词区域、播放操作 |
| 番茄钟 | 模块色点 + 等宽倒计时，暂停时静态暂停标记 | 当前目标、暂停/继续、结束 |
| 时间轴 | 日进度 + 可选下一事件时间，不滚动标题 | 恢复日/月/年原展开层级 |
| 提醒事项 | 图标 + 用户选择的待办数量 | 原有列表 |
| 便笺 | 图标 + 静态短标签，不常驻正文 | 原有便笺界面 |

多个模块已 Pin 时沿用当前选中/最近固定模块，不根据曲目、倒计时或事件周期轮流替换。没有 Pin 或运行中计时，不凭空显示占位条。

## 交互与动画

1. 进入全屏后，以约 0.20–0.24 秒将当前胶囊收成极简状态；内容几何变化与不透明度同步。不播放入场粒子或弹跳。
2. 悬停只提高局部亮度，默认不展开。鼠标经过顶边、菜单或切换标签不应触发大面板。
3. 点击可见两翼/小胶囊才临时展开。面板打开后保持正常按钮、键盘编辑和滑块拖动；不覆盖硬件刘海区域作为点击目标。
4. Esc 或关闭将面板收回极简状态，不取消 Pin。离开后可按既有延迟收回；编辑和拖动时不自动收回。
5. 退出全屏恢复进入前的模块、固定状态和展开层级，不把「全屏临时展开」写入桌面偏好。
6. 系统菜单打开时保持极简尺寸和位置，暂停刷新，不争抢系统菜单层级或鼠标。切换 Space 稳定后只进行一次布局过渡，避免闪烁或追随窗口不停移动。减少动态效果时直接切换。

## 显示器与应用规则

- 以显示器维护全屏、形态及位置。只在选定的工作屏幕显示一次；移动鼠标不应导致 UI 在屏幕间追逐。
- 用公开系统信息和窗口状态尽量区分普通最大化、原生全屏、网页视频全屏与分屏。若更精确的检测确实需要新的辅助功能权限，另行说明，不为几何判断静默扩大权限。
- 应用规则使用 bundle ID 保存「刘海贴边 / 小胶囊 / 侧边挂签」及位置，第一版不承诺长期记住单个 Space 的私有 ID。
- 相同应用内的网页或文档内容无法可靠地自动判断是否存在遮挡；提供本次位置调整和手动偏好，不读取页面正文进行猜测。
- 默认不向多屏重复铺开常驻面板。无刘海或尺寸不足时回退另一个可见形态，不能自动隐藏。

## 实现顺序与验收

先审阅尺寸稿，再加入独立的 presentation state（桌面 / 全屏常驻 / 临时展开），保持模块模型和 Pin 数据不变；随后接入显示器几何、鼠标命中和可中断动画。无需修改发布签名或授权身份。

验证至少覆盖：编辑器原生全屏、浏览器普通全屏与网页视频、PDF 阅读、演示、游戏样式无边框窗口、分屏、无刘海外屏、不同缩放及负坐标屏幕；系统菜单/工具栏出现、全屏快速切换、多个 Pin、输入/拖动中收回、退出全屏恢复。

原生预览已检查：两翼几何与相机间隙、负坐标/无刘海回退、真实浮层首击、不获取键盘焦点、菜单期间保持可见、生产 AppDelegate 展开/收回、迟到动画与桌面展开状态恢复。AppKit 窗口约束和坐标取整已按实际窗口检查修正。源码没有新增权限请求，不读取网页或文档正文。

这些检查使用虚构数据、自建窗口与注入的全屏状态。真正的跨应用、Space、菜单避让与点击穿透仍需要现场验证；分屏和特殊层级的独占游戏可能不被现有窗口几何识别。当前不宣称「每一个全屏页面」已兼容。更新包由使用者下载与安装验证。
